# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины
*   **Объём памяти:** 2048 МБ
*   **Количество ядер:** 2
*   **Объём диска:** 12 ГБ

## 2. Сетевые интерфейсы
*   **Адаптер 1 (enp0s3):** 
    *   Тип: NAT
    *   Полученный адрес: 10.0.2.15/24
    *   Назначение: Доступ в интернет, проброс портов для SSH.
*   **Адаптер 2 (enp0s8):** 
    *   Тип: VirtualBox Host-Only Ethernet Adapter
    *   Полученный адрес: 192.168.56.101/24
    *   Назначение: Прямое взаимодействие с хост-машиной (Windows), доступ к сервисам без проброса портов.

## 3. Правило проброса портов
*   **Порт хостовой системы:** 2222
*   **Порт гостевой системы:** 2222
*(Примечание: изначально порт гостя был 22, но после изменения конфигурации SSH он был перенастроен на 2222).*

## 4. Учётные записи
*   **Имя:** devops
*   **Принадлежность к группам:** devops, sudo (административные права).
*   **Способ аутентификации:** Вход только по SSH-ключу (ED25519). Вход по паролю отключен.

## 5. Служба SSH
*   **Порт:** 2222
*   **Изменённые директивы и их значения (в файле /etc/ssh/sshd_config.d/99-hardening.conf):**
    *   `PermitRootLogin no` (запрет входа под root)
    *   `PasswordAuthentication no` (запрет входа по паролю)
    *   `PubkeyAuthentication yes` (вход по ключу)
    *   `PermitEmptyPasswords no` (запрет пустых паролей)
    *   `MaxAuthTries 3` (лимит попыток входа)
    *   `LoginGraceTime 30` (время на авторизацию)
    *   `AllowUsers devops` (разрешен только пользователь devops)
    *   `X11Forwarding no` (запрет графического проброса)
    *   `ClientAliveInterval 300` и `ClientAliveCountMax 2` (таймауты соединения)
*   **Расположение файла конфигурации:** `/etc/ssh/sshd_config.d/99-hardening.conf` (дополняющий файл). Основной файл `/etc/ssh/sshd_config` не изменялся, создана резервная копия `/etc/ssh/sshd_config.backup`.
*   **Примечание:** Служба `ssh.socket` отключена, используется классический `ssh.service`.

## 6. Правила межсетевого экрана
*   **Политики по умолчанию:** 
    *   Входящий трафик (incoming): **deny** (запрещен).
    *   Исходящий трафик (outgoing): **allow** (разрешен).
*   **Перечень правил (ufw status):**
    *   `2222/tcp LIMIT IN` — SSH (с ограничением частоты подключений).
    *   `80/tcp ALLOW IN` — HTTP.
    *   `443/tcp ALLOW IN` — HTTPS.

## 7. Снимки состояния
*   **01-clean-install:** Создана и настроена виртуальная машина, проверены все адреса
*   **02-keys-configured:** Создан после настройки SSH-ключей и конфигурации файла ~/.ssh/config.
*   **03-ssh-hardened:** Создан после ужесточения конфигурации SSH (отключение паролей, смена порта).
*   **04-nginx-https** Создан после формирования сертификата для https и настроек пернаправления http на https

## 8. Веб-сервер
*   **Устанавливаемый пакет:** `nginx` (версия 1.24.0 в Ubuntu 24.04)
*   **Путь к конфигурации ресурса:** `/etc/nginx/sites-available/devops-site`
    *   Активация выполнена через символическую ссылку: `/etc/nginx/sites-enabled/devops-site`
    *   Дефолтный конфиг `/etc/nginx/sites-enabled/default` удален.
*   **Каталог ресурса:** `/var/www/devops-site`
    *   **Владелец:** `devops:devops`
    *   **Права:** `755` для каталога, `644` для файлов (обеспечивается флагом `--chmod=D755,F644` в скрипте деплоя).
*   **Пути к сертификату и ключу:**
    *   **Сертификат:** `/etc/ssl/certs/devops.crt` (права `644`, владелец `root:root`)
    *   **Ключ:** `/etc/ssl/private/devops.key` (права `640`, владелец `root:ssl-cert` для доступа Nginx)
*   **Команда формирования сертификата:** 
    `sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/ssl/private/devops.key -out /etc/ssl/certs/devops.crt -subj "/CN=devops.local" -addext "subjectAltName=DNS:devops.local"`
*   **Срок действия сертификата:** 365 дней.

## 9. Контейнеризация
*   **Способ установки Docker Engine:** Официальный репозиторий Docker (пакет `docker-ce`), версия 29.0.0 (или та, что вывела команда `docker version`).
*   **Участники группы docker:** Пользователь `devops` добавлен в группу `docker`.
*   **Расположение проекта на сервере:** `~/app` (домашняя директория пользователя `devops`).
*   **Расположение файла .env и его права:** `~/app/.env`, права `600` (владелец `devops`).
*   **Публикуемые порты и адреса:** 
    *   Приложение: `127.0.0.1:5000` (доступно только локально для Nginx).
    *   База данных (PostgreSQL/Redis): порт `5432` (или `6379`) **не публикуется**.
*   **Именованные тома:** 
    *   `app_db_data` — для хранения данных PostgreSQL (или `devops-kr2_redis_data` для Redis).
*   **Конфигурация обратного прокси-сервера:** В Nginx добавлен блок `location /app/`, который проксирует запросы на `http://127.0.0.1:5000/` с передачей заголовков `Host`, `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`.
